# Unity Lua System Specification

## 文書の目的

本書は、Lua 公式実装を利用して Unity（C#）と Lua を連携する仕組みの方針および仕様を整理する。

現時点では設計検討の初期段階であるため、確定した要求と今後決定する設計事項を分けて記載する。議論によって決まった内容は、本書へ継続的に反映する。

## 目標

- C 言語で実装された Lua 公式ライブラリを利用し、Unity の C# コードから Lua を操作できるようにする
- Unity 固有機能へ依存しない、最小限の Lua 連携機能を提供する
- C# と Lua の双方向から関数を呼び出し、引数や値を受け渡せるようにする

## スコープ

### 対象

- Lua 公式ライブラリの組み込みとライフサイクル管理
- C# からの Lua コードの読み込みおよび実行
- C# からの Lua 関数呼び出し
- C# と Lua の間での変数および引数の受け渡し
- Lua から呼び出せる C# 関数の登録
- Lua からの C# 関数呼び出し
- 実行エラーを C# 側で検出できる仕組み

### 対象外

- Lua からの `GameObject` の生成および操作
- Lua からの Unity `Component` の取得および操作
- Unity API の自動公開
- Unity の型やオブジェクトを包括的に Lua へバインドする仕組み
- ゲーム固有機能を標準で提供する高水準 API

必要になったゲーム固有機能は、利用側が明示的に C# 関数として Lua へ公開することを基本方針とする。

## 機能要件

### C# から Lua への操作

- Lua 実行環境を生成および破棄できる
- Lua スクリプトまたは Lua コードを読み込んで実行できる
- 名前などで対象の Lua 関数を指定して呼び出せる
- Lua 関数へ引数を渡せる
- Lua 関数の戻り値を C# 側で受け取れる
- Lua の変数へ値を設定できる
- Lua の変数から値を取得できる

### Lua から C# への操作

- C# 関数を Lua から参照可能な関数として登録できる
- Lua から登録済みの C# 関数を呼び出せる
- Lua から C# 関数へ引数を渡せる
- 必要に応じて C# 関数の戻り値を Lua 側で受け取れる

## 非機能要件

- 公開 API は用途を満たす最小限のものにする
- Unity 固有型への暗黙的な依存を持たせない
- Lua のスタック操作やネイティブリソースの管理を利用側へ極力露出しない
- Lua 実行時エラー、型変換エラー、未登録関数の呼び出しを診断可能にする
- ネイティブリソースを確実に解放できる所有権モデルを定義する
- Unity が対応する対象プラットフォームごとの差異を考慮できる構造にする

## 初期設計方針

以下は今後の議論の出発点であり、現時点では確定仕様ではない。

1. Lua 公式ライブラリをネイティブプラグインとして Unity へ組み込む
2. Lua C API を C# の P/Invoke 層から呼び出す
3. P/Invoke の宣言と Lua スタック操作を低水準層へ隔離する
4. 利用側には、実行環境、関数呼び出し、値変換、C# 関数登録を扱う高水準 API を公開する
5. Unity 固有機能は高水準 API に組み込まず、利用側が必要な C# 関数だけを明示的に登録する

想定する責務の分離は次のとおりとする。

- **Native Lua**: Lua 公式実装と Lua C API を提供する
- **Native Interop Layer**: P/Invoke 宣言、呼び出し規約、ネイティブ関数の公開を扱う
- **Lua Runtime Layer**: Lua state の生成、破棄、スクリプト実行、スタック整合性、エラー処理を扱う
- **Value Conversion Layer**: C# と Lua の値の相互変換を扱う
- **Function Binding Layer**: C# から Lua、および Lua から C# への関数呼び出しを扱う
- **Public API**: 利用側が直接使用する最小限の API を提供する

## 設計時に決定する事項

### Lua 実装

以下を初期実装の方針とする。

- Lua 5.4.9を採用する
- Lua公式ソースを `Native/Lua/lua-5.4.9` に同梱する
- CMakeを利用してLua公式ソースとC# callback用の薄いbridgeから `unitylua54.dll` を生成する
- 最初の対象をUnity 6000.3.21f1、Windows Editor、x86_64とする
- システム本体を `Packages/com.daitokuamy.unityluasystem` に配置する
- 生成したDLLを `Packages/com.daitokuamy.unityluasystem/Runtime/Plugins/x86_64` に配置する
- `Assets` 配下は利用側のサンプルコードや動作確認用アセットに使用する

Lua標準ライブラリは初期の技術検証ではすべて有効にし、公開範囲の制限は基本動作の確認後に決定する。

### 値の受け渡し

- 最初に対応する値型
- `nil` と C# の `null` の扱い
- 数値型の変換規則
- Lua table の対応範囲
- 複数戻り値の表現方法
- 対応していない型を受け取った場合の挙動

### 関数呼び出し

- Lua 関数の参照方法
- C# 関数の登録単位と名前空間
- 可変長引数の扱い
- C# delegate の保持期間と GC 対策
- コールバック中に例外が発生した場合の扱い

### ライフサイクルと安全性

- Lua state の所有者と破棄方法
- 破棄後の API 呼び出しに対する挙動
- メインスレッド以外からの利用可否
- 複数の Lua state を許可するか
- Lua のパニックおよび実行時エラーの伝達方法
- Lua スタックを呼び出し前後で正常に保つ方法

### スクリプトの供給

- Lua スクリプトを文字列、ファイル、Unity アセットのどの形式で受け取るか
- スクリプトの検索パスとモジュール読み込みの扱い
- ビルド後の Lua スクリプトの配置方法

### API 設計

- 同期 API のみを提供するか
- 戻り値をジェネリック API、専用の値型、または明示的な変換 API のどれで表現するか
- Lua 関数や Lua table の参照を長期間保持できるようにするか
- 例外を使用する範囲と、結果型でエラーを返す範囲

## 初期段階で想定する最小値型

最初の実装候補として、以下の型に限定する案を検討する。

| Lua | C# |
| --- | --- |
| `nil` | `null` または専用の Lua 値表現 |
| `boolean` | `bool` |
| `number` | `long` / `double` |
| `string` | `string` |
| `function` | Lua 関数参照 |

Lua table、userdata、thread は、必要性と所有権モデルを整理した後に対応範囲を決定する。

## 完了条件のたたき台

- Unity 上で Lua state を生成および破棄できる
- C# から Lua コードを実行できる
- C# から Lua 関数へ値を渡し、戻り値を取得できる
- Lua から登録済みの C# 関数へ値を渡し、戻り値を取得できる
- Lua の実行エラーを C# 側で内容付きで取得できる
- Lua state の破棄後にネイティブリソースや delegate が残存しない
- 上記の動作を自動テストで確認できる
